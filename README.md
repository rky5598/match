# Совместимость по векторам (match)

Сервис подбора совместимости: один человек создаёт профиль и получает
ссылку-приглашение, второй открывает её, заполняет свой профиль — и обе стороны
видят совместимость по слоям, с флагами и зеркальными отчётами.

Без регистрации и сервера: профиль зашит в саму ссылку. Всё работает на стороне
браузера.

## Состав пакета (v2.3)

| Файл | Роль |
|---|---|
| `match.html` | Единственная страница: главная -> профиль -> ссылка -> матч -> результат |
| `compatibility_module.js` | Движок: три слоя счёта, флаги, трение пиков, кодек профиля в URL, встроенные golden-тесты |
| `styles.css` | Тёмная тема интерфейса |
| `index.html` | Редирект на match.html (чтобы корень GitHub Pages открывал сервис) |
| `golden_tests.json` | Контрольный корпус калибровки v2.3 (эталон для юнит-тестов и портов) |
| `README.md` | Этот документ |

## Развёртывание на GitHub Pages

1. Создайте репозиторий на GitHub (например, `match`).
2. Загрузите **все шесть файлов в корень** репозитория
   (Add file -> Upload files, либо git push).
3. Откройте Settings -> Pages.
4. Source: **Deploy from a branch**, ветка **main**, папка **/ (root)**. Save.
5. Через 1–3 минуты сервис доступен по адресу
   `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`.

### Признак, что всё работает

Вверху страницы — зелёный баннер:
«Проверка движка: golden-тесты 9/9 пройдены — калибровка v2.3 подтверждена».

Если баннер красный — прочитайте его текст: он называет конкретную проблему
(какой тест разошёлся или какой файл не найден).

### Частые проблемы

- **«Ошибка страницы: движок не загрузился»** — `compatibility_module.js` не
  подгружен: проверьте, что файл лежит в корне репозитория рядом с `match.html`,
  и сделайте жёсткое обновление страницы (Ctrl+F5 / Cmd+Shift+R), чтобы сбросить кэш.
- **Старая версия после обновления** — кэш браузера: Ctrl+F5.
- **README вместо сервиса на корневом адресе** — должен присутствовать `index.html`
  с редиректом (входит в пакет v2.3).

## Как пользоваться

### Создание ссылки-приглашения

1. Откройте страницу -> «Создать свой профиль и ссылку».
2. Выставьте уровни 8 векторов (0–4).
3. Отметьте повторяющуюся тьму (степень 1 — «бывает», 2 — «стало чертой»).
4. Отметьте живущий свет — то, что реально отдаёте людям.
5. Выберите ведущий вектор и тип отношения (партнёр / друг / бизнес).
6. «Создать ссылку» -> скопируйте ссылку вида `…?p=eyJ2Ijpb…&r=partner`.
7. Отправьте второму человеку любым мессенджером.

### Матч

1. Второй человек открывает ссылку и видит первый профиль (с расшифровкой).
2. Заполняет свой профиль в той же форме.
3. Нажимает «Рассчитать совместимость».
4. Обе стороны видят: счёт с живым потолком, слои, флаги и два зеркальных
   отчёта — «что мне дают» и «что я даю».
5. Тип отношения можно переключать на экране результата — счёт пересчитается.

## Как читать результат

- **Счёт** — вторичная сводка. Главный показатель — слои и флаги.
- **Живой потолок** зависит от типа: партнёр 65%, друг 75%, бизнес 80%.
  Число выше потолка — признак бага калибровки, а не радость.
- **Флаги**: совпадение тьмы (в партнёрстве — обнуление счёта), тьма в ведущем
  доме, трение пиков (вершина уровня 4 стоит энергии), конкуренция за руль (бизнес).
- **Профиль-дверь 2.0** — эталон живой пары в golden-корпусе: 63% партнёр,
  60% друг, 74% бизнес. Любой новый матч можно сравнивать с ним по слоям.

## Архитектурные правила (зафиксированы в калибровке)

1. Счёт не может вернуть 100 живой паре: максимум достижим только конструктом,
   а конструкт проигрывает живому профилю из-за трения пиков.
2. Свет и тьма стоят на одном атоме (закон 24): живой профиль обязан нести тьму.
3. Профиль — снимок (закон 14): уровни растут, счёт меняется. Это навигатор, не приговор.
4. Пара без обмена не может набрать баллы на чужой силе: пустой профиль — 1%.

## Ограничения

- Нет регистрации, истории и сохранений: всё живёт в ссылках.
- Профиль в URL виден всем, кто получил ссылку — не публикуйте её в открытых чатах.
- Работает в современных браузерах (нужны btoa/atob и URLSearchParams).
