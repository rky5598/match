# Совместимость по векторам — match (v2.2)

Статический сервис подбора совместимости: без сервера, без регистрации, без базы данных.
Профиль человека кодируется в URL, матчинг считается на клиенте.

## Состав

| Файл | Роль |
|---|---|
| `match.html` | Единственная страница: главная → профиль → ссылка → матч → результат |
| `compatibility_module.js` | Движок: три слоя счёта, флаги, трение пиков, кодек профиля в URL, встроенные golden-тесты |
| `styles.css` | Тёмная тема интерфейса |
| `index.html` | Редирект на `match.html` — чтобы GitHub Pages открывал сервис с корневого адреса |
| `golden_tests.json` | Контрольный корпус калибровки v2.1 (эталон для юнит-тестов и портов) |
| `README.md` | Этот документ |

## Развёртывание на GitHub Pages

1. Создайте репозиторий на GitHub (например, `match`).
2. Загрузите **все файлы из архива в корень репозитория** (Add file → Upload files).
3. Settings → Pages → Source: «Deploy from a branch», ветка `main`, папка `/ (root)` → Save.
4. Через 1–2 минуты сервис доступен по адресу `https://ЛОГИН.github.io/ИМЯ-РЕПО/`.
5. Признак работоспособности: зелёный баннер «Проверка движка: golden-тесты 9/9 пройдены».
   Красный баннер с перечнем случаев — движок и эталоны разошлись, отчёты будут заблокированы.
6. Локальная проверка без GitHub: просто откройте `match.html` двойным кликом (сервер не нужен).

Важно: корневой адрес Pages открывает `index.html`. В пакете это редирект на `match.html`.
Если предпочитаете без редиректа — переименуйте `match.html` в `index.html` и удалите файл-редирект.

## Как пользоваться

**Создание ссылки-приглашения.** Откройте страницу → «Создать свой профиль и ссылку» →
выставьте уровни 8 векторов (0–4), отметьте повторяющуюся тьму (1 — «бывает», 2 — «стало чертой»),
живущий свет, ведущий вектор, тип отношения → «Создать ссылку» → скопируйте ссылку вида
`…?p=eyJ2Ijpb…&r=partner` и отправьте второму человеку любым мессенджером.

**Матчинг.** Второй человек открывает ссылку, видит первый профиль, заполняет свой →
обе стороны получают: общий счёт, слои (свет / двери / оси), флаги и зеркальные отчёты
«что мне дают» и «что я даю».

**Типы отношений** (меняются веса слоёв и флагов):

| Тип | Ключевое отличие |
|---|---|
| Партнёр | полный вес флагов; удвоение ведущего −20; совпадение тьмы — вето (0%) |
| Друг | главный слой — свет (60); удвоение ведущего = +10; флаги демпфированы (−5) |
| Бизнес | главное — разделение ролей; удвоение ведущего = −25 (конкуренция за руль) |
| Родитель → ребёнок | свет течёт сверху; совпадение тьмы −20 (передача сценария), невроз×невроз −30 |
| Ребёнок → родитель | свет 30 и двери 30 — основа принятия |

## Golden-корпус v2.1 (залочен)

| Случай | Партнёр | Друг | Бизнес |
|---|---|---|---|
| USER × профиль-дверь 2.0 | 63 | 60 | 74 |
| USER × конструкт-«идеал» | 60 | — | — |
| USER × антипортрет | 0 (вето) | — | — |
| USER × USER | 0 (вето) | 74 | 34 |
| USER × пустой профиль | 1 | — | — |

Правила калибровки: сотня достижима только конструктом без тьмы — это баг, а не радость;
живые пары живут в диапазоне 40–75%; трение встречных пиков −10.5 за каждый вектор,
где у обоих уровень 4 (конструкт-«идеал» обязан проигрывать живому профилю).

## Ограничения и приватность

- Профиль в URL виден любому, кто получил ссылку: не публикуйте её в открытых чатах.
- Историй и аккаунтов нет: обновить профиль — сгенерировать новую ссылку.
- Движок целиком клиентский; golden-тесты выполняются при каждой загрузке страницы.
