# Сервис совместимости (match.html)

Сервис подбора совместимости.

## Файлы

| Файл | Роль |
|---|---|
| `match.html` | Единственная страница: главная → профиль → ссылка → матч → результат |
| `compatibility_module.js` | Движок: три слоя счёта, флаги, трение пиков, кодек профиля в URL, golden-тесты |
| `styles.css` | Тёмная тема интерфейса |
| `golden_tests.json` | Контрольный корпус калибровки v2.1 (эталон для юнит-тестов и портов) |
| `README.md` | Этот документ |

## Развёртывание на GitHub Pages

1. Создай репозиторий на GitHub (например, `svp-match`), ветка `main`.
2. Положи в корень все 5 файлов (через веб-интерфейс: Add file → Upload files).
3. Settings → Pages → Source: **Deploy from a branch** → Branch: `main`, папка `/ (root)` → Save.
4. Через 1–2 минуты сервис доступен по адресу `https://ТВОЙ_ЛОГИН.github.io/svp-match/`.
5. Открой страницу: баннер сверху должен показать «golden-тесты 9/9 пройдены». Если показан красный баннер — движок расходится с эталоном, обнови файлы.

## Как пользоваться

**Создание ссылки-приглашения.** Открой страницу → «Создать свой профиль и ссылку» → выставь уровни 8 векторов (0–4), отметь повторяющуюся тьму (степень 1 — «бывает», 2 — «стало чертой»), живущий свет, ведущий вектор, тип отношения → «Создать ссылку» → скопируй ссылку вида `…?p=eyJ2Ijpb…&r=partner` и отправь второму человеку любым мессенджером.

**Матчинг.** Второй человек открывает ссылку — видит карточку первого профиля, заполняет свой, нажимает «Показать совместимость». Обе стороны получают: общий счёт с живым потолком, слои (двери / оси / свет), красные флаги и зеркальные отчёты «что даёт кому».

**Типы отношений** — движок один, конфиги весов разные:
- `partner` — полный вес флагов; удвоение ведущего и совпадение тьмы — красные.
- `friend` — главный слой свет; удвоение ведущего = **плюс** (счёта друг о друге нет); флаги демпфированы.
- `business` — главное разделение ролей; удвоение ведущего = конкуренция за руль (−25).
- `parent` / `child` — свет течёт сверху; совпадение тьмы = передача сценария (−20), невроз×невроз −35.

## Калибровка v2.1 — почему нельзя получить 100

1. **Трение пиков (закон 16/24):** каждый вектор уровня 4 у любой из сторон стоит −10 баллов. Реализованная вершина — это цена, а не только актив.
2. **Живой потолок:** выводится рядом со счётом. 100 — математический предел формулы, недостижимый для живых людей.
3. **Golden-корпус:** 9 зафиксированных случаев. Проверяются при каждой загрузке страницы; при расхождении вывод отчётов блокируется.
4. **Ключевые эталоны:** конструкт-«идеал» (все двери, ноль тьмы, три пика) = **60%** — проигрывает живому профилю-двери (63%); антипортрет = **0%**; пара «сам с собой» как партнёры = **0%** (удвоение+невроз), как друзья = **74%** (общий свет решает); пустой профиль = **1%**.
5. **Число — вторично:** главный показатель — вердикт по слоям и флаги. Счёт — сводка, не решение.

## Архитектурные правила (не нарушать)

- **Детерминизм:** одинаковые входы → одинаковый выход. LLM допустима только как переписчик тона, не как логик.
- **ГРАНИЦА всегда:** блок «карта не диагноз» печатается в каждом отчёте без исключений.
- **Сильный дефицит партнёра — не минус:** отсутствие сильного вектора у человека — «простор», а не «негодность».
- **Красная зона пары:** при 2+ флагах и счёте ниже 25% движок пишет вердикт «осторожно» и рекомендует живого специалиста (закон 22).

## Ограничения

- Профиль зашит в URL и виден всем, кто получил ссылку. Не отправляй ссылку в публичные чаты.
- Аккаунтов и истории нет: обновить профиль — сгенерировать новую ссылку.
- Движок — чистая арифметика по таблицам системы; это карта взаимодополнения, не научный тест совместимости.
